# Gemini normal-client capability preflight

> Implement with subagent-driven development or executing-plans, using independent review and sequential root-owned browser/build verification.

**Goal:** Establish whether the actual owned Gemini model consumer has the prerequisites for a later protected text trial, without initiating provider operations or exposing private values.

**Architecture:** A self-contained synchronous MAIN function reads only exact own data descriptors and the already-created bound consumer's references. Chrome pins it to the already validated native document during the pending model receipt. Application owns the strict fixed result contract; presentation explains the result without claiming generation readiness.

**Tech stack:** Existing TypeScript, WXT, Zod, Vitest and Playwright; no new dependency or permission.

**Status:** Metadata source-classifier acceptance complete; ready for a local checkpoint. Final verification passed 190 pure-provider checks, 630 unit tests plus type/build checks, 15 installed checks (23.6s) and 176 synthetic browser checks (3.4m). Exact installed native verification passed ownership, original declaration provenance, selected services and protection, and classified the configured initial framework-stream route as `unsupported/transport-rpc`. The current account is not a supported/verified cold-native candidate; no request or response was tested. Artifact identities, earlier guard failures and public-source byte differences belong to [validation](../testing/validation.md).

## Scope and constraints

- Preserve existing web login/subscription, source conversation, foreground, metadata intent, cancellation, session ID/status boundary and model cleanup ownership.
- Accept only the source profile documented in [the transport investigation](../research/background-web-transport.md). A missing export, unsupported context, incorrect declaration relation or unexpected descriptor is unsupported; do not guess aliases, skip local overrides or hydrate a service.
- MAIN receives no DOM node or private context from ISOLATED. Reacquire exactly one attached visible compact `gem-button[data-test-id="bard-mode-menu-button"]`, its exact nearest `bard-mode-switcher[data-test-id="bard-mode-switcher"]`, and one owning visible inner button. Use only the GEM-BUTTON host's own context; another layout, duplicate or missing context is unsupported. Do not search ancestors for a context or use broad selector fallbacks. Never enumerate general namespaces, views, tokens or services.
- Never invoke provider factories, injectors, observers, protection, store, connection, generation or history methods. Do not inspect authentication, bootstrap siblings, headers, body, packet values or private model keys.
- Export only a strict fixed result: candidate, or unsupported with a fixed reason. Keep flags, references and context IDs inside the page. Neither result authorizes a request.
- A registered prewarm manager is unsupported in this first scope. Do not clear it, disable it, choose another transport or alter flags. The actual new connection's dispatch callback cannot be proven before its later creation.

## Later generation boundary

This deliverable does not implement a request. An outer API call counter is insufficient because the current SDK has internal reconnect/fallback paths. A later narrow cold-native trial must bind one final approved packet, one subscription and one genuine connection callback, retain its guards through actual MAIN cancellation and queued effects, and confirm exact raw saved-history completion. Missing capture or teardown after a possible connect is uncertain, never proof of a request that did not begin. Those gates must be resolved before generation; this preflight must not present itself as a successful response or a general sending capability.

## Corrections from evidence

The first environment-cache profile and its native owner/owner-slot results are historical evidence. Public source showed that normal tooltip setup can insert one LContainer around the owned component view. Independent review also found that a root cached service can differ from the model component's resolved node-local provider. The replacement profile therefore preserves exact slot ownership, follows the known three declaration links and reads the component's own selected service. It does not unwrap private composite injectors, certify root factory provenance or assert absence of transparent proxies. Artifact-specific regression and native results belong to [validation](../testing/validation.md).

The later native `owner-declaration-3-binding` result localized the mismatch after parent/node/index/iB validation. Both inspected public byte versions show normal `aSb` insertion overwriting child5 with the insertion TNode, while `ESb` records the original declaration container at child16. The correction validates that exact original container against declarationParent[81] and its marker/parent/TNode; it is not an insertion-container fallback. Current source bytes differ from the historical source despite matching k/ck, so names alone do not establish source equivalence. Corrected native artifacts passed this provenance and the final consumer/service/protection guards. Neither that progress nor the fixture candidate establishes a native candidate or response.

The earlier aggregate transport result and oa-first transport-session result are historical. Public source establishes Aa as the initial route selector: only native Aa true requires session oa; Nd selects the Aa false initial legacy branch and is irrelevant to native eligibility. Final native metadata classified Aa false/Nd false as framework streaming RPC. This is the configured initial route, not observed physical dispatch or proof of response. A normal-SDK request-owned `Uwa.setParam("rt") → own Rj.send` guard remains a source-investigation candidate; it is not implemented or proved by this preflight. Do not patch global fetch, force flags or infer a request boundary from a descriptor.
